# Derived Project Schemas

Recognize derived identity from explicit project markers/instructions or a valid generator manifest. Core is valid without milestones, backlog, or a full historical context tree.

Project instructions decide which maintained files require frontmatter. Existing schema-free README/instructions and raw intake stay schema-free. Do not add required owner/repo/source-version labels throughout the project.

Preserve an existing `agentic_rails_source_version` where it records real starter ancestry. Missing ancestry stays unknown; do not fabricate `0.0` or treat the current local document version as its source baseline. A manifest's exact generated bytes and hashes own framework update ancestry.

Preserve actual owner/repo values. Git config identifies a contributor, not necessarily project ownership. Replace an explicit identity placeholder only from reliable maintained project metadata or the user's accepted identity. Otherwise report that file's unresolved identity.

A repair can normalize required local version formatting, but it does not advance framework provenance, change a published product version, or rewrite completed execution records. Historic captures require a specifically requested repair with their original parser schema.
