# Target and Source Discovery

Resolve the target from explicit input, then the current project. Inspect project instructions, repository status, existing identity/configuration, and context links. A Core project may have only instructions, a purpose/design note, README, and baseline manifest; absence of milestones is not drift.

Resolve the starter in this order: provided path, recorded/configured source location, established workspace sibling `agentic_rails_context_starter`. Verify the candidate using its README, profiles, generator, and templates rather than its folder name alone. Inspect the installed generator's help and documented interface before invoking it. Never search private directories broadly when a known workspace path suffices.

Resolve intake from the user message, named files, or previously supplied session material. If none exists, ask for the missing source while recording any completed preflight. A path that exists is not authorization to rewrite its project.

Generated identity needs concrete project name, repo, owner, and purpose. A Git contributor is not necessarily the project owner. Missing required identity can be resolved from explicit project metadata or user input; do not fake it.

For current generator editions, pass explicit `generate`, destination, profile, host, name, repo, owner, purpose, and only adopted commands/constraints. Use its dry-run mode first. Existing output collisions require baseline update or selective adoption, never a forced overwrite.

Inspect actual build/package configuration before declaring a stack pack. Record any selected packs as declarations; claiming installation or activation requires separate host evidence.
