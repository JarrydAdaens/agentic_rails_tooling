# Update Discovery and Scope

Resolve target from input or current project root. Read its instructions and relevant context. Inspect Git status, identity, adopted profile/commands/stack declarations, baseline manifest, and product version files without changing them.

Resolve source from supplied path, project/workspace configuration, or a known sibling `agentic_rails_context_starter`. Validate README, generator, profiles, templates, revision, and uncommitted source content. A local checkout can be stale; record its identity instead of claiming it is the newest release.

Core absence of milestone/backlog folders is valid. An older layout does not require restructuring for selective instruction updates. Follow links to actual maintained truth and retain established historical paths.

Classify ownership per file: trusted generated baseline, explicitly owned framework section with proven ancestry, project-owned truth, history, or unknown. Select only requested framework changes. Unknown ownership enters manual comparison rather than destructive normalization.

Read the current generator's help/README before command construction. Recorded generation inputs are the authority for normal updates; profile or identity change belongs to a separately reviewed migration.
