# Intake Synthesis

Keep raw intake distinct from maintained truth. Preserve it at the established Dictation path, or use a descriptive kebab-case file under `context/dictations-tier-0/` relative to the target root. Record source links and any redactions. Late intake enriches existing decisions only where compatible or explicitly superseding them.

## Minimal synthesis

For Core, populate concrete project identity, purpose, actual commands, unusual constraints, and conditional links to relevant context. A brief design note can express the accepted architecture; unknowns need not expand into a large manual.

Do not reproduce the canonical Rails overview in the project. Keep reusable framework identity and host wrappers consistent with the selected generator output. Route architecture work to design, continuation to the current plan, and adopted harness modules to their instructions.

## Optional delivery context

Planned delivery needs a concrete current outcome, acceptance, dependency ordering, and one status owner. High consequence additionally needs targeted independent review, required checks, and recovery evidence. Proposed controls are not verified controls.

A requested roadmap can use maintained Design, Milestone, Story, and backlog structures. Expand only near-term work with evidence. Preserve stable IDs, links, accepted statuses, and historic plans. Do not force every discrete change into a milestone or create empty files for every context tier.

Use `rails-planning` for one substantial implementation plan and `rails-milestone-planning` for a deliberately selected milestone. CER is optional and qualitative. Keep uncertainty in the artifact affected by it.

## Identity and baseline

Apply identity edits only to selected maintained project content after a match preview. Raw intake, evidence, vendored code, and history remain untouched. Product-version identity is independent of framework/document version.

The generator records the framework baseline before synthesis. Leave that source baseline intact while enriching project files. Future updates compare baseline, newly rendered framework source, and enriched project bytes; replacing the baseline with project bytes destroys ownership evidence.
